# Sega Mega Drive / Genesis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline; the tasks share interfaces too tightly for per-task subagents). Steps use checkbox (`- [ ]`) syntax.

**Goal:** a `genesis` machine plugin that runs retail Mega Drive / Genesis software with correct picture, sound and input, accurate before fast.

**Architecture:** new family repository `retroclawd-sega` (submodule `machines/sega`), plugin `sega_machine_plugin`. `mc68000` and `z80` from `retroclawd-crates`; VDP, YM2612, SN76489, cartridge format and the machine live in the family. Master-clock scheduler: `step()` runs one 68000 instruction and brings the Z80, VDP and sound chips to the same master time lazily (the Atari `events.rs` model). No ABI change.

**Tech Stack:** Rust 2024, `#![forbid(unsafe_code)]`, serde + bincode for states, `rcasm`/`rcdis` from `retroclawd-tools` for probe ROMs, Python 3 `ctypes` for the libretro oracle host.

**Spec:** `docs/superpowers/specs/2026-10-24-sega-genesis-design.md`

## Global Constraints

- Reference emulators may be run and their source read for understanding (owner, 2026-10-24); copy no code, table, constant or comment; confirm each fact by a document or two-oracle probe; tables that hardware derives by formula are generated by documented `const fn`s (spec section 1).
- Every hardware fact has a row in `machines/sega/docs/hardware-facts.md` labelled `[D]/[H]/[O]/[H?]` with its source; an I/O address without a fact stops the machine with a bounded report (`--diag-file`).
- Machine time only from the scheduler: no wall clock, no floats in timing. `#![forbid(unsafe_code)]` in every crate.
- Never commit goldens, ROMs, firmware (`bios_MD.bin`, `sk.bin`, ...), datasheets/PDFs or downloaded cores. Downloads go in their own directory; downloaded files are untrusted: never print their contents, run Python that reads them with `-I`.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. Explicit `git add` paths only (never `-A` at a repo root). Do not commit the host's untracked `AGENTS.md`, `.clinerules/`, `.cursor/`, `.opencode/`, `.windsurf/`, `.github/copilot-instructions.md`, `docs/*.pdf`.
- Stop and ask only for: creating the GitHub repository, any push, a pin bump in `retroclawd-crates` that is pushed, and fetching third-party binaries for the first time (cores). Everything else is a ledger ruling.
- Option ids use underscores; machine key names come from the plugin's own tables (one source for the key list and the handler).

## Review Focus

- ROM with an odd size, a size not a power of two, a header-less file, an `.smd` interleaved dump: must load or fail with a message, never panic.
- A game that never unlocks TMSS or writes the wrong string: VDP stays locked, machine keeps running, no crash.
- VDP command stream edge cases: DMA with length 0, DMA source wrapping a 128 KB boundary, writes to the data port with the wrong code, VRAM address odd, sprite link loops: bounded, no panic, no hang.
- Z80 reset/busreq glitches: 68000 reads the Z80 area without the bus; Z80 bank register pointing at unmapped space.
- Savestate from another ROM, another region or a truncated file: refused with a message.

## Phase 3: accuracy mode (T20-T26). Exit: the probe suite, with known gaps listed.

Phase 3 starts with a short refinement of this section into its own plan file (as `2026-10-22-atari-st-phase3.md` did), once Phase 2 exposed what the oracles disagree about. Contents:

- **T20 `--accuracy accurate|fast` option** (`Execution mode` convention) and per-bus-cycle 68000 stepping through `M68kBus::sync` and the bus transaction order; devices brought up to the cycle of each access (`events.rs`, `waits.rs` pattern).
- **T21 68000 bus timing:** DTACK delays for VDP port, Z80 area, I/O, ROM refresh stalls, bus contention while the Z80 holds `BUSREQ`; each delay a probe-measured `[O]` row.
- **T22 Z80 contention:** access to the 68000 window costs the documented extra cycles; Z80 stalls during VDP DMA from the 68000 bus; YM busy bit duration.
- **T23 VDP slot timing:** FIFO depth 4 with slot availability, data-port write stalls, DMA per-slot transfer rates by mode and by active/blanked display, HV counter by pixel, HBlank/VBlank edges at pixel resolution, HINT/VINT placement against the 68000's sample point, sprite/tile fetch limits per line, CRAM dots and mid-line register changes (`render_exact` with per-clock register log as the Atari Shifter did).
- **T24 probes `p20..p50`** for each of the above, built with `mkrom.py`, recorded against two oracles; manifest `exact` or `known-gap` with the measured difference.
- **T25 public test ROMs:** `tools/fetch_diagnostics` entries (hash-pinned, freely redistributable ones only; search for VDP, Z80, YM2612 and I/O test ROMs), run in the manifest, results recorded.
