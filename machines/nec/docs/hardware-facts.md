# PC Engine / TurboGrafx-16 hardware facts

Every hardware fact the PC Engine code uses is a row here. Tags: `[H]` published hardware documentation as the author knew it (the
HuC6280, HuC6270 and HuC6260 manuals and the community's PC Engine technical notes; **recalled, not re-fetched during the first
implementation run**, so each such row is a claim to check against a source before it is relied on), `[O]` observed in the reference
(Beetle PCE Fast, Mednafen's PC Engine core, a black box through its libretro build), `[T]` observed in a game running here and in the
reference, `[H?]` unresolved. No code, table or constant is copied from any emulator.

## Processor (HuC6280)

| ID | Fact | Source | Used by |
|---|---|---|---|
| H1 | The HuC6280 is a 65C02 (`BRA`, `PHX/PHY/PLX/PLY`, `STZ`, `TSB/TRB`, `INC A/DEC A`, `(zp)` indirect, `JMP (abs,X)`, `BIT` with immediate/zp,X/abs,X, `RMBn/SMBn`, `BBRn/BBSn`) plus `CLA CLX CLY`, `SAX SAY SXY`, `ST0 ST1 ST2`, `TAM TMA`, `TST`, `SET`, `BSR`, `CSL CSH` and the block transfers `TII TDD TIN TIA TAI`; the other opcodes are two-cycle `NOP`s | [H] | `huc6280` |
| H2 | Eight mapping registers `MPR0-7` each select an 8 KB bank of a 2 MB physical space: physical = `MPR[logical >> 13] << 13 \| logical & $1FFF`. `TAM mask` writes A to every `MPRn` whose bit is set; `TMA mask` reads the lowest selected one. `MPR7` is 0 after reset; the others are undefined (a game sets them) | [H]; [T] every game starts with `TAM` sequences | `huc6280` |
| H3 | Zero page is physical-page-mapped at logical `$2000-$20FF` and the stack at `$2100-$21FF` (so `MPR1` must be the RAM bank `$F8`) | [H]; [T] games map `$F8` at `MPR1` first | `huc6280` |
| H4 | Vectors in bank `MPR7` at the top of the logical space: `$FFF6` IRQ2/`BRK`, `$FFF8` IRQ1 (video), `$FFFA` timer, `$FFFC` NMI, `$FFFE` reset. Priority IRQ2, IRQ1, timer | [H]; [T] Air Zonk's table at `$1FF6-$1FFF` of bank 0 | `huc6280`, `pcengine` |
| H5 | The processor resets to the slow speed (1.79 MHz, 12 master clocks a cycle); `CSH` selects fast (7.16 MHz, 3 master clocks), `CSL` slow again | [H]; [T] every game executes `CSH` first | `huc6280`, `pcengine` |
| H6 | Cycle counts: immediate/implied 2, zero page 4, absolute 5, indirect forms 7, read-modify-write zp 6 and abs 7, branch 2 not taken and 4 taken, `BBRn/BBSn` 6 and 8, `PHA/PHX/PHY` 3, `PLA/PLX/PLY` 4, `JSR/RTS/RTI` 7, `BSR` 8, `BRK` and interrupt entry 8, `TAM` 5, `TMA` 4, `ST0-2` 4, `TST` 7 (zp) and 8 (abs), `SXY/SAX/SAY/CSL/CSH` 3, block transfers 17 + 6 x length | [H]; [T] games' timing loops run in step with the reference (RAM counters agree within 2 percent over 100 frames, `probe`) | `huc6280` |
| H7 | Decimal mode: `ADC`/`SBC` adjust the result, flags N and Z are valid, and the instruction takes one extra cycle | [H] | `huc6280` |
| H8 | The T flag: `SET` makes the next `ORA`, `AND`, `EOR` or `ADC` operate on the byte at `$2000 + X` instead of A (the result goes back there, A is unchanged) and take 3 more cycles; any other instruction clears it | [H] | `huc6280` |
| H9 | An interrupt pushes PC and P (B clear; `BRK` sets B), sets I and clears D and T. `CLI` and `PLP` take effect after the next instruction: an interrupt asserted at the time is taken only after one more instruction | [H]; [T] Final Soldier's handler does `CLI` then reads the video status to drop the line, and re-entered itself forever without this delay | `huc6280` |

## Machine

| ID | Fact | Source | Used by |
|---|---|---|---|
| M1 | Physical banks: `$00-$7F` the HuCard (8 KB pages, up to 1 MB), `$F8-$FB` the 8 KB of RAM (mirrored), `$FF` the hardware page; everything else reads `$FF` | [H] | `pcengine` |
| M2 | Hardware page `$FF` (offset within the page): `$0000-$03FF` video controller, `$0400-$07FF` colour encoder, `$0800-$0BFF` sound, `$0C00-$0FFF` timer, `$1000-$13FF` I/O port, `$1400-$17FF` interrupt registers; each repeats inside its window | [H]; [T] games address them at `$0000-$0005` with `MPR0 = $FF` | `pcengine` |
| M3 | Timer: a 7-bit counter ticks every 1024 high-speed CPU cycles (3072 master clocks, 6993 Hz) while the CPU runs fast or slow; `$0C00` write sets the reload value, read gives the counter; `$0C01` bit 0 starts it (the counter is loaded from the reload on the start). At zero the counter reloads and the timer interrupt is raised, so the period is `reload + 1` ticks. `$1403` (write any value) acknowledges the timer interrupt. Before the timer is first started the counter reads `$7F` (the reference shows `$80`: bit 7 is the data bus). `[H?]` Battle Royale starts a reload-0 timer and then loops until it reads a non-zero counter, which the reference does within one frame (it stores `$7F`) and we never see: the counter probably shows `$7F` briefly at each underflow; a 36-clock window was tried and did not help (the interrupt entry takes the instruction slot), so it is open | [H]; [T] Air Zonk's sound driver runs from a reload-0 timer and its RAM counters keep the reference's pace; [O] `build.py` `pce-timer5.pce` stores 48 counter reads and the sequence is the same here and in the reference | `pcengine` |
| M4 | Interrupt registers: `$1402` is the disable mask (bit 0 IRQ2, 1 IRQ1, 2 timer; 1 = disabled), `$1403` read gives the requests (the same bits). IRQ1 is the video controller's line, level-triggered | [H] | `pcengine` |
| M5 | The I/O port `$1000`: write bit 0 SEL and bit 1 CLR. A two-button pad reads its directions (bit 0 up, 1 right, 2 down, 3 left, active low) with SEL = 1 and its buttons (bit 0 button I, 1 button II, 2 Select, 3 Run) with SEL = 0. Bits 4-5 read 1 with no CD-ROM unit, bit 6 tells the console (set = TurboGrafx-16 here, clear = PC Engine) and bit 7 reads 1. A multitap adds a counter that CLR resets and a rising SEL steps, selecting pads 1-5 | [H]; [O] the reference reads the pad bits as above; `[H?]` the exact polarity of bit 6 and bit 7 (games here run with either) | `pcengine` |
| M6 | A HuCard image has an optional 512-byte header (a file length of 512 modulo 8192). Some US dumps have every byte bit-reversed: the reset vector's high byte at offset `$1FFF` must be `$E0` or more, else the reversed bytes are tried | [H]; [T] the owner's 417 files all boot | `pce-card` |
| M7 | Power-of-two cards repeat through the 1 MB space (`page = bank mod pages`). A 384 KB card is two chips: bank bit 6 clear selects the 256 KB chip (repeated every 32 banks), set selects the 128 KB chip (repeated every 16 banks) | [H]; [T] Cadash and Super Momotarou Dentetsu map banks `$4C`/`$4F` and only run with this rule | `pce-card` |
| M8 | The 2.5 MB Street Fighter II' Champion Edition card shows its first 512 KB at banks `$00-$3F` and a window of 512 KB at banks `$40-$7F` chosen by a write to `$1FF0-$1FF3` (block 1-4; block 0 at power on) | [H]; [T] the game reaches its title in step with the reference | `pce-card` |

## Video (HuC6270, HuC6260)

| ID | Fact | Source | Used by |
|---|---|---|---|
| V1 | The video controller has 32K words of VRAM and registers `$00-$13` selected by writing the register number to port 0. Port 2 is the data low byte and port 3 the high byte: the write of the high byte completes a 16-bit write (VRAM word at `MAWR` for register 2, with `MAWR` stepping by the increment), a low-byte write of the other registers takes effect at once. Reading port 0 gives the status and clears it | [H]; [T] | `huc6270` |
| V2 | Registers: `$00 MAWR`, `$01 MARR`, `$02 VWR/VRR`, `$05 CR`, `$06 RCR`, `$07 BXR`, `$08 BYR`, `$09 MWR`, `$0A HSR`, `$0B HDR`, `$0C VPR`, `$0D VDW`, `$0E VCR`, `$0F DCR`, `$10 SOUR`, `$11 DESR`, `$12 LENR`, `$13 SATB` | [H] | `huc6270` |
| V3 | `CR`: bits 0-3 enable the collision, overflow, raster and vertical-blank interrupts, bit 6 sprites, bit 7 background, bits 11-12 the increment (1, 32, 64, 128). `DCR`: bit 0 the sprite-table-DMA-end interrupt, bit 1 the VRAM-DMA-end interrupt, bit 2 source decrement, bit 3 destination decrement, bit 4 repeat the sprite DMA every vertical blank | [H] | `huc6270` |
| V4 | The status flags are only raised while their enable bit is set: the raster flag with `CR` bit 2, the vertical-blank flag with bit 3, collision and overflow with bits 0 and 1, the DMA-end flags with `DCR` bits 0 and 1. The interrupt line is a flag and its enable | [T] Soldier Blade's handler tests the raster bit first and hung when both flags were reported; Air Zonk's RAM copy of the status differs from the reference's by the DMA bit when it is raised without its enable | `huc6270` |
| V5 | `HDR` (`$0B`): bits 0-6 are the display width in 8-dot cells minus one (`$1F` = 256 dots), bits 8-14 the display end. `HSR` (`$0A`) holds the sync width and display start. `VPR` (`$0C`): bits 0-4 the vertical sync width and bits 8-15 the display start | [H]; [T] a swapped reading showed a 40-dot picture | `huc6270` |
| V6 | The vertical layout: the first active line is `VSW + VDS + 2` counted from the first line of the frame (19 for the usual `VSW = 2`, `VDS = 15`), `VDW + 1` active lines follow, then `VCR` lines. The frame's line count is the sum, so a game with `VDW = $FF` has a 279-line frame; the vertical-blank flag rises on the first line after the active lines | [H]; [T] Idol Hanafuda Fan Club (`VDW = $FF`) never saw a vertical blank in a 263-line frame; with the sum its frame length agrees with the reference | `huc6270`, `pcengine` |
| V7 | The raster compare counter is 64 on the first active line and counts up by one a line; the raster flag is raised on the line it equals `RCR` | [H]; [T] | `huc6270` |
| V8 | The background is a virtual screen of 32/64/128 by 32/64 cells (`MWR` bits 4-5 and 6) of 8x8-dot cells; a map entry is 16 bits: tile number in bits 0-11 and palette in bits 12-15. A tile is 16 words: eight words of planes 0 (low byte) and 1 (high byte), then eight of planes 2 and 3; the leftmost dot is bit 7. The line drawn is `BYR + n` (reloaded from `BYR` on the first active line, and on the line after a write to it); the horizontal offset is `BXR` | [H]; [T] | `huc6270` |
| V9 | Sprites: 64 entries of four words in the sprite attribute table (copied from VRAM by the DMA): Y (bits 0-9, screen line + 64), X (bits 0-9, dot + 32), pattern (bits 1-10 select the 64-word pattern block), attributes (bits 0-3 palette, bit 7 priority over the background, bit 8 width 32, bits 12-13 height 16/32/64, bit 11 horizontal flip, bit 15 vertical flip). A 16x16 pattern is 64 words: planes 0-3 of 16 words each, a row a word, the leftmost dot bit 15. A wider or taller sprite uses the following 64-word blocks (width: block + 1; height: block + 2 per 16 lines), with the low pattern bits ignored | [H]; [T] the legal screens, titles and shooters match the reference | `huc6270` |
| V10 | At most 16 sprite cells (a 32-wide sprite is two) are drawn on a line, the lowest-numbered first; more raise the overflow flag. A sprite dot of index 0 is transparent; the lower-numbered sprite wins a dot, and if its priority bit is clear and the background dot is not transparent the background shows. Sprite 0 overlapping another sprite raises the collision flag | [H]; `[H?]` collision only for sprite 0 (the reference was not probed) | `huc6270` |
| V11 | The sprite attribute table DMA copies 256 words from `SATB` at the first vertical blank after a write to `SATB`, and at every vertical blank with `DCR` bit 4 | [H]; [T] | `huc6270` |
| V12 | VRAM-to-VRAM DMA runs when `LENR` is written: `LENR + 1` words from `SOUR` to `DESR`, each stepping up or down by `DCR` bits 2-3. It is done at once here (the real transfer takes about two cycles a word) | [H]; `[H?]` the transfer time | `huc6270` |
| C1 | The colour encoder has 512 palette entries of 9 bits (blue bits 0-2, red 3-5, green 6-8), written through an address register (`$0402/$0403`) and a data register (`$0404/$0405`, the high-byte access steps the address). Background palettes are entries 0-255, sprite palettes 256-511; entry 0 of a palette is transparent and shows entry 0 of palette 0 | [H]; [T] | `huc6260` |
| C2 | `$0400` bits 0-1 choose the dot clock (5.37, 7.16, 10.74 MHz: 256, 352, 512 dots across), bit 7 black and white. A line is 455 CPU cycles (1365 master clocks) and a frame 262 or 263 lines | [H]; [O] the reference reports 59.82 frames a second (21 477 272 / (1365 x 263) = 59.83) | `pcengine` |
| C4 | The lines outside the picture (and the dots beside it) show palette entry `$100`, the first colour of the first sprite palette: a card that never sets it shows the encoder's power-on content (white in the reference, black here) | [O] the reference's overscan rows on the test card `pce-input.pce`, which sets only entries 0 and 1 | `pcengine` |
| C3 | The reference shows a 243-line window: 3 lines above the first active line and 240 below it (a taller display is cut), 256 dots for the 5.37 MHz clock and 352 for 7.16 MHz, nothing wider than the clock's nominal width (a display register asking for 264 dots shows 256) | [O] picture sizes of 30 games, the row of Air Zonk's text (3 lines lower in the reference) | `pcengine` |

## Sound (HuC6280 PSG)

| ID | Fact | Source | Used by |
|---|---|---|---|
| P1 | Six channels share one set of ports at `$0800-$0809`: `$0800` channel select, `$0801` main balance (left bits 4-7, right 0-3), `$0802/$0803` the 12-bit frequency, `$0804` control (bit 7 on, bit 6 direct D/A, bits 0-4 level), `$0805` the channel balance, `$0806` waveform data, `$0807` noise (channels 5 and 6: bit 7 enable, bits 0-4 rate), `$0808/$0809` the LFO | [H] | `huc6280-psg` |
| P2 | The sound clock is the master clock over 6 (3.579545 MHz). A channel steps through its 32-sample, 5-bit waveform every `frequency` clocks (0 counts as 4096): 3 579 545 / (32 x frequency) Hz | [H]; [O] register `$0FE` plays 441 Hz here and in the reference | `huc6280-psg` |
| P3 | Waveform writes (`$0806`) go to the channel's write pointer, which steps after each write, only while the channel is off; with bit 6 set and bit 7 clear a write sets the direct D/A sample instead. Switching the channel off resets the write pointer | [H] | `huc6280-psg` |
| P4 | The level is 1.5 dB a step in the channel level (5 bits) and 3 dB in each of the balances (4 bits); a balance of 0 is silent | [H]; the overall gain is calibrated, not derived (P5) | `huc6280-psg` |
| P5 | One channel at full level, balances `$F` and a square wave of full swing is a square of amplitude 0.160 (RMS 0.1604) in the reference's float output; the output gain is set to this. The output is AC coupled (a 20 Hz high-pass) | [O] `scenarios/build.py pce-tone.pce` against `audio_compare.py` | `huc6280-psg` |
| P6 | Noise (channels 5 and 6) is a 15-bit shift register clocked every `64 x (32 - rate)` sound clocks; the LFO makes channel 2's frequency follow channel 1's output by a shift of 0, 4 or 8 bits, channel 1 then runs at `frequency x LFO rate` | `[H?]` the noise period and the LFO details were written from memory and not compared with the reference | `huc6280-psg` |
